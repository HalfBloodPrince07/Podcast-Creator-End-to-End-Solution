# Setup Guide — Exact Reproduction

This guide reproduces the **`Podcast` conda environment** used to develop
this project. It is more than a `pip install -r requirements.txt`: a few
packages need version pins that violate their declared dependencies, one
file inside `diffusers` needs a small patch after install, and on Windows
the conda-shipped `ffmpeg` has to be replaced with a build that includes
`libass` (otherwise burned subtitles silently fail).

The fastest path is the automated script at
[`scripts/setup_podcast_env.ps1`](scripts/setup_podcast_env.ps1)
(Windows) or [`scripts/setup_podcast_env.sh`](scripts/setup_podcast_env.sh)
(Linux/macOS). The manual steps below explain what those scripts do and
why.

---

## TL;DR — automated reproduction

### Windows (PowerShell, Anaconda installed)

```powershell
# 1. clone the repo
git clone <this-repo> Podcast-Creator-End-to-End-Solution
cd Podcast-Creator-End-to-End-Solution

# 2. run the bootstrap (creates the conda env, installs everything,
#    applies the FLAX patch, swaps ffmpeg, verifies imports)
powershell -ExecutionPolicy Bypass -File scripts\setup_podcast_env.ps1
```

The script accepts `-EnvName Podcast` (default), `-CudaIndex auto`
(`auto` | `cu130-nightly` | `cu121` | `cu124` | `cpu`), and
`-SkipFfmpegSwap` if you already have a libass-enabled ffmpeg on PATH.

### Linux / macOS

```bash
git clone <this-repo> Podcast-Creator-End-to-End-Solution
cd Podcast-Creator-End-to-End-Solution
bash scripts/setup_podcast_env.sh
```

The Linux script skips the ffmpeg swap (most distro ffmpegs already
have libass).

## What the lockfile contains

[`requirements.lock.txt`](requirements.lock.txt) is the literal
`pip freeze` output of the working `Podcast` env. Versions of note:

| Package | Pin | Why this version |
|---|---|---|
| `torch` | `2.11.0+cu130` | RTX 5060 Ti is **Blackwell (sm_120)**. Earlier prebuilt CUDA wheels have no sm_120 kernels and Chatterbox falls back to CPU. If you don't have a Blackwell GPU, pick a stable index (see below). |
| `transformers` | `5.2.0` | Hard-pinned by `chatterbox-tts==0.1.7`. |
| `diffusers` | `0.31.0` | **Violates** chatterbox's `==0.29.0` pin but chatterbox still imports cleanly. Required for the SDXL + CogVideoX video bed. **Do not go above 0.33.x** — `LoRACompatibleLinear` was removed in 0.34 and chatterbox needs it. |
| `accelerate` | `1.13.0` | Matches the Blackwell torch nightly. |
| `peft` | `0.19.1` | Needed by the diffusers 0.31 ↔ transformers 5.x bridge. |
| `huggingface-hub` | `1.14.0` | New `hf_hub_download` keyword API used by transformers 5.x. |
| `chatterbox-tts` | `0.1.7` | The newest version that imports against transformers 5.x with the diffusers bump above. |
| `faster-whisper` | `1.2.1` | CTranslate2 4.7.1 ships sm_120 kernels. |
| `numpy` | `2.2.6` | Required for torch 2.11 ABI. |
| `gradio` | `6.8.0` | Pulled in by chatterbox; not used by our UI. |

The lockfile was sanitized so `packaging` is `==26.2` instead of the
local conda file URL.

### Torch index URL — pick one

`torch==2.11.0+cu130` is **not on PyPI**. Install it from a PyTorch index
that matches your CUDA:

| Hardware | Command |
|---|---|
| RTX 5060/5070/5080/5090 (Blackwell, sm_120) | `pip install --pre torch==2.11.0+cu130 torchvision==0.26.0+cu130 torchaudio==2.11.0+cu130 --index-url https://download.pytorch.org/whl/nightly/cu130` |
| RTX 30/40-series + most older Ada/Ampere | `pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu124` |
| GTX 1080-class / older | `pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121` |
| No GPU | `pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cpu` |

If you pick a non-cu130 torch, **remove the three `+cu130` lines from
`requirements.lock.txt`** before piping it into pip, or use
`requirements.base.txt` (generated by the setup script) which already
strips them.

## Manual reproduction (step by step)

### 1. Create the conda env

```bash
conda create -n Podcast python=3.10.20 -y
conda activate Podcast
```

The env name in our setup is literally `Podcast`. If you change it, also
update any IDE interpreter pointers — `agents/visual_agent.py` and the
LangGraph imports do not hard-code the env name.

### 2. Install torch FIRST (CUDA-specific)

Pick a line from the table above and run it. Doing this **before** the
bulk install prevents pip from pulling a CPU wheel as a transitive dep.

### 3. Install everything else from the lockfile

```bash
pip install -r requirements.lock.txt
```

You will see warnings like:

```
chatterbox-tts 0.1.7 requires diffusers==0.29.0, but you have diffusers 0.31.0
chatterbox-tts 0.1.7 requires transformers==4.46.3, but you have transformers 5.2.0
```

**These are expected.** chatterbox imports cleanly anyway; the pins
exist only to flag breakage that does not actually occur for our usage.

### 4. Patch `diffusers` for the missing `FLAX_WEIGHTS_NAME`

`transformers` 5.x removed `FLAX_WEIGHTS_NAME` when it deprecated Flax.
`diffusers` 0.31 still imports it for SDXL pipeline metadata. Without
the patch:

```
ImportError: cannot import name 'FLAX_WEIGHTS_NAME' from 'transformers.utils'
```

Apply it cross-platform:

```bash
python scripts/apply_flax_patch.py
```

That script wraps the failing import in a `try / except ImportError` and
falls back to the historical string `"flax_model.msgpack"`. It is
**idempotent** — running it twice is a no-op.

Manual edit if you prefer: open
`<env>/lib/site-packages/diffusers/pipelines/pipeline_loading_utils.py`
and change

```python
from transformers.utils import FLAX_WEIGHTS_NAME as TRANSFORMERS_FLAX_WEIGHTS_NAME
```

into

```python
try:
    from transformers.utils import FLAX_WEIGHTS_NAME as TRANSFORMERS_FLAX_WEIGHTS_NAME
except ImportError:
    TRANSFORMERS_FLAX_WEIGHTS_NAME = "flax_model.msgpack"
```

**Re-apply after any `pip install --upgrade diffusers`** — pip overwrites
the file.

### 5. (Windows only) Install an ffmpeg build with `libass`

The conda-forge ffmpeg that comes with the env is built **without**
`--enable-libass`. The `subtitles` / `ass` filters silently produce
empty video. Replace the binaries in-place with Gyan.dev essentials:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install_ffmpeg_libass.ps1
```

That script:
1. Downloads Gyan.dev `ffmpeg-release-essentials.zip`.
2. Backs up the existing `ffmpeg.exe` / `ffprobe.exe` as `*.condabak`.
3. Copies the Gyan binaries into `<env>\Library\bin\`.
4. Greps `ffmpeg -filters` for `subtitles ... libass` to confirm.

`conda install -c conda-forge ffmpeg` will overwrite this swap. Re-run
the script if you ever do.

On Linux, install ffmpeg from your package manager — `apt install
ffmpeg`, `dnf install ffmpeg`, `brew install ffmpeg` — and verify with
`ffmpeg -filters | grep subtitles`.

### 6. Install the frontend deps

```bash
cd frontend
npm install
npm run build      # for production
# or: npm run dev  # for hot-reload
```

### 7. Copy environment variables

```bash
cp .env.example .env
# edit .env to point at your LM Studio (default http://localhost:1234/v1)
```

### 8. Verify

```bash
python -c "
import torch; print('torch', torch.__version__, 'cuda?', torch.cuda.is_available())
from diffusers import StableDiffusionXLPipeline; print('SDXL import OK')
import chatterbox; print('chatterbox import OK')
from faster_whisper import WhisperModel; print('whisper import OK')
"
```

Expected output:

```
torch 2.11.0+cu130 cuda? True
SDXL import OK
chatterbox import OK
whisper import OK
```

If `torch.cuda.is_available()` is `False` on a machine with a GPU, you
picked the wrong torch index URL. Uninstall and redo step 2.

### 9. Run the app

```bash
python app.py            # backend on :8000
cd frontend && npm run dev   # frontend on :5173
```

Open <http://localhost:5173>.

## External services (not pip-installable)

These have to be running for a full pipeline run:

1. **LM Studio** with a chat model loaded and the local server enabled
   on `:1234`. We develop against `google/gemma-4-e4b` (reasoning); the
   `chat()` call in `llm_client.py` defaults to a 32K `max_tokens`
   budget because reasoning models burn through smaller budgets inside
   `<think>` blocks before producing any answer text.
2. **HuggingFace cache** — first SDXL run downloads ~7 GB of weights to
   `~/.cache/huggingface`. First CogVideoX cue triggers a one-time
   **~21.5 GB** download of `THUDM/CogVideoX-5b`. Set
   `TRANSFORMERS_CACHE` in `.env` if you want them elsewhere.
3. **NVIDIA driver** new enough to expose CUDA 13. On Windows, that is
   driver `≥ 565.xx`. Older drivers will load the cu130 torch but every
   kernel launch will fail at runtime.

## What the setup script actually does (for auditors)

`scripts/setup_podcast_env.ps1` runs these steps in order:

1. Detects whether a conda env named `Podcast` already exists. If yes,
   asks before nuking; if no, creates it with `python=3.10.20`.
2. Activates the env in the current shell.
3. Calls `nvidia-smi` to detect GPU compute capability. If Blackwell
   (`9.x` / `12.x`), pre-installs torch cu130 nightly; otherwise
   cu124 stable. CPU fallback if no GPU at all.
4. Pipes `requirements.lock.txt` through pip with the torch lines
   stripped (so torch is not re-resolved).
5. Runs `python scripts/apply_flax_patch.py`.
6. Runs `scripts/install_ffmpeg_libass.ps1` unless `-SkipFfmpegSwap`
   was passed.
7. Verifies imports of torch / diffusers / chatterbox / faster-whisper.
8. Prints a green checkmark and the four follow-up commands
   (`npm install`, copy `.env`, start LM Studio, `python app.py`).

The script is **safe to re-run**. Every step is idempotent — pip's
`--upgrade-strategy only-if-needed` is the default, the FLAX patch
detects its own marker, and the ffmpeg swap skips itself when
`ffmpeg.exe.condabak` already exists.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `ImportError: cannot import name 'FLAX_WEIGHTS_NAME'` | Patch not applied (or wiped by `pip upgrade diffusers`) | Re-run `python scripts/apply_flax_patch.py` |
| Burned subtitles missing on `episode.mp4` | ffmpeg without libass | Re-run `scripts/install_ffmpeg_libass.ps1` |
| Chatterbox logs "CUDA kernel not found for sm_120, falling back to CPU" | Torch wheel without sm_120 | Reinstall torch from the cu130 nightly index |
| `torch.cuda.is_available() == False` with a GPU plugged in | Wrong torch index for your CUDA driver | Pick a different row from the torch table above |
| `bitsandbytes` int8 errors | Blackwell + bnb is unreliable | Don't use int8 on this GPU; bf16 + `enable_sequential_cpu_offload()` is what we do for CogVideoX |
| Pipeline hangs after TTS finishes | A GPU stage forgot to unload | Check `agents/post_production_agent.py` calls `unload_all_backends()` — see the GPU choreography comment block in `agents/visual_agent.py` |
| LLM returns empty strings for short prompts | Reasoning model consumed entire `max_tokens` budget inside `<think>` | Increase `max_tokens` (defaults are now 4K–32K, see `llm_client.py`) |
